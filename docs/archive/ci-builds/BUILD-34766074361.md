# Hardware package: two-launch grown-table integration (SB4E01 only)

## Why these two launches
Plain T0 (2 created files) compacts to 144323 bytes and always installs
in place (verified with the production builder: plain 153934, compacted
144323, reserve 153792). T3 likewise compacts (plain 153878, compacted
144267). So stock T0 can only ever exercise the in-place path - it is
the control, not the grown test. The grown launch needs a table that
overflows even compacted; computed below with the same builder.

## Loader install
Back up the existing `apps/usbloader_gx` dir on SD first, then install
this build's `apps/usbloader_gx` (`boot.dol` hash above). Confirm the
build on-device by launching once with no mod: not required - the card
log of each test launch must contain the new marker lines named below,
which no older build emits.

## SD mod pack (same card layout both launches)
Base: the existing `/riivolution/gxdiag/` pack (T0 `a.bin` + `b.bin`,
`gxdiag.xml`).
For launch 2 only, add 150 generated files plus one choice (exact):
- On a PC, in `/riivolution/gxdiag/T8/`, generate 150 files
  `grown0000.bin` … `grown0149.bin` (64 bytes each; content arbitrary -
  the game never opens them).
- In `gxdiag.xml`, inside the existing Test option's choices, add:
  `<choice name="P1 T8 Grown"><patch id="gx_t8"/></choice>`
  and beside the other patch definitions add:
  `<patch id="gx_t8" root="/riivolution/gxdiag">`
  `  <folder disc="/GXDiagBig" external="T8" create="true" recursive="true"/>`
  `</patch>`
- Expected table (production builder, verified): plain ≈164284,
  compacted ≈154673 - grown by ~881 bytes even compacted, so the grown
  apploader path runs rather than compaction. Fragment budget: ~152
  files, far below the 20000 shared cap.

## Launch 1 — in-place control ("P1 T0 Creates")
Expected log (must all appear): `compacted table ... STAGED`,
`fits in the room the apploader already set aside`, `OUTCOME:
FST_STAGED`. Expected outcome: normal boot (T0 files are never opened;
this proves the install path with no regression on the new build).

## Launch 2 — grown T0-big ("P1 T8 Grown")
Expected log (must all appear; any missing line invalidates the run as
a grown-path test): `virtual header serves grown size/max`,
`installs at the apploader-reported base`, apploader-reported
base/size lines, staged size ≈164284, `OUTCOME: FST_STAGED`. Must NOT
appear: `compacted table ... STAGED`, `fits in the room`.
Expected outcome: unknown - that is the experiment. T0-big files are
never opened, so this tests grown-table launch integration only, not
content consumption.

## If launch 2 does not boot
STOP after these two launches (maximum). Preserve the complete card
log (`/riivolution/usbloadergx_riivo_SB4E01.log` on the mod device),
the blink code if any (loader return), and the observed outcome
(title / black screen / loader return) with no interpretation beyond
observables. By design the log then isolates the fault: install
verification state, published words, and placement are all recorded
pre-jump. A later milestone (real grown mod with memory patches, e.g.
Spectral) follows only after launch 2 boots.
